## Phase 1：字符串比较

记录日期：2026-10-07。

### 1. 从主程序找到检查入口

`bomb.c` 中，第 73–75 行依次执行：

```c
input = read_line();
phase_1(input);
phase_defused();
```

`input` 是 `char *`，保存输入字符串的地址。`phase_1` 检查这行输入；正常返回后，主程序继续调用 `phase_defused`。

Linux / WSL x86-64 调用约定中，第一个整数或指针参数使用 `%rdi`，第二个使用 `%rsi`。主程序实际准备参数的汇编为：

```asm
0x400e32: call read_line       # 输入字符串的地址返回在 rax 中
0x400e37: mov  %rax, %rdi      # 将这个地址作为第一个参数
0x400e3a: call phase_1
```

因此，进入 `phase_1` 时，`%rdi` 中保存的是输入字符串地址。寄存器名和其中保存的值要区分；`%` 是 AT&T 汇编的寄存器标记，不表示取地址。

### 2. 查看 Phase 1 的汇编

在 GDB 中执行：

```gdb
disassemble phase_1
```

得到：

```asm
0x400ee0 <+0>:  sub  $0x8, %rsp
0x400ee4 <+4>:  mov  $0x402400, %esi
0x400ee9 <+9>:  call 0x401338 <strings_not_equal>
0x400eee <+14>: test %eax, %eax
0x400ef0 <+16>: je   0x400ef7 <phase_1+23>
0x400ef2 <+18>: call 0x40143a <explode_bomb>
0x400ef7 <+23>: add  $0x8, %rsp
0x400efb <+27>: ret
```

| 指令 | 含义 |
|---|---|
| `sub $0x8, %rsp` | 栈指针减去 8，为后面的调用调整栈空间 |
| `mov $0x402400, %esi` | 写入第二个参数；写 `%esi` 清零高 32 位，因此 `%rsi = 0x402400` |
| `call strings_not_equal` | 调用字符串比较函数，整数结果放在 `%eax` |
| `test %eax, %eax` | 按位与并设置条件码，不改写 `%eax`；返回值为 0 时，`ZF = 1` |
| `je 0x400ef7` | `ZF = 1` 时跳到栈恢复指令，跳过失败处理 |
| `call explode_bomb` | 比较结果非零时到达失败处理 |
| `add $0x8, %rsp` | 收回开头调整的 8 字节栈空间 |
| `ret` | 使用栈上的返回地址回到调用者 |

`test` 和 `je` 是独立指令，通过条件码联系：前者设置 `ZF`，后者读取 `ZF`。这里没有其他指令在两者之间改写它。

将检查路径整理为伪代码：

```text
result = 比较(输入字符串, 目标字符串)
如果 result 非零：执行 explode_bomb
否则：恢复栈指针，正常返回
```

通过条件是让比较函数自然返回 0。

### 2. 整体解题思路

第一项必须是 1。从第二项开始，每一项都必须是上一项的两倍。循环检查完第六项后返回。因此本关答案为：

```text
1 2 4 8 16 32
```

数字之间用空格，整行输入后回车，不加逗号。用户已实际运行并反馈“好通过了”，没有保存通过提示的逐字输出。

### 3. 按实际执行顺序分析

不能只从上往下读汇编。第一项检查成功时会先跳到 `0x400f30`，设置循环使用的指针，再跳回 `0x400f17`。

1. 两个 `push` 保存原来的 `%rbp`、`%rbx`，`sub $0x28,%rsp` 预留 40 字节。
2. `mov %rsp,%rsi` 传递写入地址，`read_six_numbers` 把输入字符串解析成六个整数并写入栈。
3. `cmpl $1,(%rsp)` 检查第一项。相等则 `je` 跳到 `0x400f30`，否则爆炸。
4. 两个 `lea` 初始化：`rbx = rsp + 4`，指向第二项；`rbp = rsp + 24`，指向六项之后的边界。
5. 跳回循环体：读取上一项到 `%eax`，将它加倍，与当前项比较。相等则继续，不相等则爆炸。
6. `%rbx` 加 4，指向下一项。与 `%rbp` 地址不同，就通过 `jne` 回到循环体；相同就结束。
7. `%rsp` 加回 40，逆序恢复 `%rbx`、`%rbp`，最后 `ret` 返回。

```text
检查第一项为 1
      ↓
初始化：rbx 指向第二项，rbp 指向结束边界
      ↓
当前项 == 上一项 × 2？── 否 → explode_bomb
      ↓ 是
rbx 地址加 4
      ↓
rbx != rbp？── 是 → 回到循环检查
      ↓ 否
恢复栈和寄存器，返回
```

循环开始时已经完成空间预留，下表的 `rsp` 指此时的栈顶。循环过程中这个基准不变；调用函数时临时压入的返回地址会在返回后弹出。

| 地址 | 用途 | 正确输入中的值 |
|---|---|---|
| `rsp + 0` | 第一项 | 1 |
| `rsp + 4` | 第二项 | 2 |
| `rsp + 8` | 第三项 | 4 |
| `rsp + 12` | 第四项 | 8 |
| `rsp + 16` | 第五项 | 16 |
| `rsp + 20` | 第六项 | 32 |
| `rsp + 24` | 六项之后的结束边界 | 不读取这里的整数 |

每个 `int` 占 4 字节，六项占 24 字节，不是把预留的 40 字节全部用来存输入。最后一轮检查第六项后，`rbx` 增加到 `rsp + 24`，恰好与 `rbp` 相等，循环停止。

### 4. 关键语法与寄存器

| 写法 | 含义 |
|---|---|
| `%rsp` | 寄存器中的栈顶地址值 |
| `(%rsp)` | 栈顶地址处的内存内容，读取大小取决于指令 |
| `-4(%rbx)` | 当前地址往前 4 字节处的内存内容；不是把整数减 4 |
| `lea 4(%rsp),%rbx` | 只计算 `rsp + 4`，把地址放入 rbx，不读取内容 |
| `mov -4(%rbx),%eax` | 从该地址读取 4 字节整数放入 eax |
| `add %eax,%eax` | 将 eax 中的整数加倍，没有减 1 或进行比较 |
| `cmp %eax,(%rbx)` | 按“当前项减 eax”设置标志位，不修改数据 |
| `cmp %rbp,%rbx` | 比较地址值；没有括号，所以不是比较内存中的整数 |
| `add $4,%rbx` | 移动指针，不给数组里的整数加 4 |

`cmp` 相等时 `ZF = 1`。`je` 在相等时跳转，`jne` 在不相等时跳转；它们读取前面指令设置的标志位。

本函数中 `%rbp` 保存循环结束边界，**没有用作栈帧指针**。`%rbp`、`%rbx` 都是需要由被调用者保存的寄存器（callee-saved registers），本函数修改前保存、返回前恢复。

两个不同的条件不要混在一起：`cmpl $1,(%rsp)` 检查第一项是不是 1；`cmp %eax,(%rbx)` 检查相邻两项的倍数关系。

其他分支对应哪个索引，需要读取跳转表，不能按照这些指令在列表里的先后顺序猜。本次只读取并验证了索引 `0` 的路线。

### 2. 整体解题思路

输入两个整数。第一个整数必须在 `0～7`，用来选择一个分支；分支会给 `%eax` 设置一个值，第二个整数必须与这个值相等。

本次选择第一个整数为 `0`，查表得到分支地址 `0x400f7c`。该分支设置 `%eax = 0xcf = 207`，因此得到一组答案：

```text
0 207
```

这是一组通过验证的答案，不要求找全所有分支。

```text
解析两个整数
    ↓
成功赋值两个项目？── 否 → explode_bomb
    ↓ 是
第一个整数在 0～7？── 否 → explode_bomb
    ↓ 是
用第一个整数查跳转表，进入对应分支
    ↓
分支设置 eax 的比较值
    ↓
第二个整数等于 eax？── 否 → explode_bomb
    ↓ 是
恢复栈指针，返回，通过第三关
```

### 3. 按实际执行顺序分析

**准备栈空间与函数参数。** `sub $0x18,%rsp` 使栈指针减去 24，预留空间，但不初始化这些内存。下面的 `rsp` 都指减去 24 后、位于 `phase_3` 内的栈指针。

| 位置 | 存放内容 | 本次答案解析后的值 |
|---|---|---|
| `rsp + 8` | 第一个整数，4 字节 | `0` |
| `rsp + 12` | 第二个整数，4 字节 | `207` |

`lea` 计算地址：`lea 0xc(%rsp),%rcx` 得到 `rcx = rsp + 12`。`0xc` 是十六进制的 12；这条指令不会读取或修改那个地址里的整数。

在 GDB 中查看格式字符串：

```gdb
x/s 0x4025cf
```

本次读到 `"%d %d"`。`%d` 是十进制整数的格式说明符，与汇编寄存器前面的 `%` 没有关系。Linux x86-64 下，这次调用的参数如下：

| 参数顺序 | 寄存器 | 用途 |
|---|---|---|
| 第一个 | `%rdi` | 已经读入的输入字符串地址，进入 `phase_3` 时就已传入 |
| 第二个 | `%rsi` | 格式字符串 `"%d %d"` 的地址 |
| 第三个 | `%rdx` | 第一个整数的存放地址 `rsp + 8` |
| 第四个 | `%rcx` | 第二个整数的存放地址 `rsp + 12` |

`mov $0x4025cf,%esi` 写低 32 位，同时将 `%rsi` 高 32 位清零，所以完整 `%rsi` 的值就是这个地址。寄存器能保存数值或地址，具体含义由当前代码决定；`%rsp` 则有栈指针这一特殊用途。

**调用并检查解析结果。** `sscanf` 从已有字符串解析数据，不会在调用时再次向终端询问输入。对应的 C 语义为：

```c
int first, second;
int count = sscanf(input, "%d %d", &first, &second);
```

`first`、`second` 是为理解而起的变量名。`__isoc99_sscanf` 是 C 库中的函数版本名；`@plt` 表示通过过程链接表入口调用库函数。

调用前的 `mov $0,%eax` 是可变参数调用准备，让 `%al = 0`，表示本次没有使用向量寄存器传参。调用返回后，`%eax` 被返回值覆盖，表示成功赋值的项目数量。

`cmp $1,%eax` 和 `jg` 组合要求返回值大于 1；当前格式只有两项，因此必须成功赋值两个整数。

**函数规则与调用约定要分开。** `sscanf` 是标准库函数，其功能需要查函数说明；寄存器命名不能告诉我们它返回什么。它从第一个参数指定的字符串中，按第二个参数指定的格式解析数据，并通过后续参数给出的地址写入结果。它返回成功赋值的项目数量，不是传入参数数量，也不是某个输入整数。

```c
int a, b;
int count = sscanf("0 207", "%d %d", &a, &b);
// 4 个参数；成功赋值 2 个项目：a = 0，b = 207，count = 2。
// 若输入改成 "0 abc"，仍有 4 个参数，但只成功赋值 a，返回 1。
```

能解析什么由格式决定：`%d` 对应整数，`%s` 对应字符串，所以返回值也不单指数字数量。我们这道题的格式恰好是两个 `%d`。

Linux x86-64 调用约定规定这些整数/指针参数依次放入 `rdi、rsi、rdx、rcx`，`int` 返回值放入 `eax`。第一个整数的存放地址是函数的第三个参数 `rdx`，不要混淆两个编号。通用寄存器的用途会随指令改变：

```text
调用前 eax = 0：让 al 传递“未使用向量寄存器传参”的调用信息
sscanf 返回后 eax = 2：成功赋值两个项目
mov 8(%rsp),eax 后 eax = 0：换成第一个输入整数，用作查表索引
所选分支执行后 eax = 207：换成第二个整数应等于的值
```

`eax` 是 `rax` 的低 32 位；它不是第一个参数寄存器，也不永远保存返回值。要沿着实际执行顺序追踪赋值。

**检查第一个整数的范围。** `cmpl $7,8(%rsp)` 读取第一个 4 字节整数，与 7 比较。`ja` 使用无符号大小关系：无符号大于 7 就爆炸。负数按其 32 位位模式解释为无符号数时也很大，例如 `-1` 对应 `4294967295`，所以同样无法通过。由此推导出合法范围是 `0～7`。

**选择分支，再检查第二个整数。** `mov 8(%rsp),%eax` 将第一个整数装入索引寄存器。间接跳转随后读取跳转表中的地址。索引 `0` 进入 `0x400f7c`，执行 `mov $0xcf,%eax`，将原来的索引覆盖为 `207`；随后直接跳到公共比较位置 `0x400fbe`。

`cmp 0xc(%rsp),%eax` 比较第二个整数与当前 `%eax`。`je` 要求这两个值相等，即比较后 `ZF = 1`，并不是要求 `%eax = 0`。相等就跳过爆炸调用，最后 `add $0x18,%rsp` 收回空间，`ret` 返回。

### 4. 跳转表与关键语法

当前间接跳转：

```asm
jmp *0x402470(,%rax,8)
```

分成三步理解：

1. 计算表项位置：`0x402470 + rax × 8`。
2. 从该位置读取一个 8 字节的代码地址。
3. 跳到读出的代码地址执行。

`0x402470` 是表的起点，`%rax` 是索引，乘以 `8` 是因为每个表项存一个 8 字节地址。**第一个整数有 0～7 共 8 种选择，与每项占 8 字节，是两件不同的事。**

| 第一个整数（索引） | 表项所在位置 | 本次是否读取目标 |
|---|---|---|
| `0` | `0x402470` | 是，目标为 `0x400f7c` |
| `1` | `0x402478` | 未读取 |
| `2` | `0x402480` | 未读取 |
| `3` | `0x402488` | 未读取 |

十六进制地址也按数值相加，例如 `0x402478 + 8 = 0x402480`。

本次只需要索引 `0` 的目标，执行：

```gdb
x/gx 0x402470
```

实际得到：

```text
0x402470:       0x0000000000400f7c
```

冒号左侧是**存放目标地址的位置**，右侧是**真正要跳去的代码地址**。`jmp` 不是直接跳去 `0x402470`，也不是因为 `0x400f7c` 刚好排在下一行才执行它。

若要一次查看所有八个表项，可用 `x/8gx 0x402470`；它只是查看内存，不会使程序执行或跳转。只跟踪某次输入时，在执行到这条 `jmp` 前可用 `x/gx (0x402470 + $rax * 8)`，读取当前选中的那一项。

| 写法 | 含义 |
|---|---|
| `mov $数值,%寄存器` | 将立即数放入寄存器，不读取该数值指向的内存 |
| `lea 8(%rsp),%rdx` | 计算地址 `rsp + 8` |
| `mov 8(%rsp),%eax` | 从地址 `rsp + 8` 读取 4 字节内容 |
| `cmpl 源,目标` | 按“目标减源”设置标志位；`l` 表示 4 字节，不保存减法结果 |
| `jg` / `ja` | 分别判断有符号大于 / 无符号大于 |
| `je` | `ZF = 1` 时跳转；跟在 `cmp` 后表示两操作数相等 |
| `jmp 0x400fbe` | 直接跳到指令中写明的地址 |
| `jmp *内存操作数` | 先读取内存里保存的目标地址，再跳转 |

### 3. 按执行顺序理解递归

**先看参数从哪里来。** 调用前明确执行 `mov $14,%edx`、`mov $0,%esi`、`mov 8(%rsp),%edi`。因此第一次进入函数时：

| 寄存器 | 数值 | 根据内部用法赋予的含义 |
|---|---|---|
| `%edi` | 输入的第一个整数 | 目标 `target` |
| `%esi` | `0` | 下界 `low`，范围的起点 |
| `%edx` | `14` | 上界 `high`，范围的终点 |

“下界、上界”是根据程序用途起的解释性名称，不是寄存器名字自带的含义。递归调用前会修改某个参数，因此后面的调用中 `esi` 不一定还是 0，`edx` 也不一定还是 14。

**计算中点。** 第一组普通运算依次得到：

```text
eax = edx = 14
eax = eax - esi = 14 - 0 = 14
ecx = eax = 14
ecx 逻辑右移 31 位 = 0
eax = 14 + 0 = 14
eax 算术右移 1 位 = 7
ecx = rax + rsi = 7 + 0 = 7
```

`shr` 左边补零；`sar` 左边补原来的符号位。`shr 31 → add → sar 1` 组合处理有符号数除以 2 的向零截断。在本题目标位于有效范围内的调用路径上，`high - low` 非负，修正项为 0，中点可以理解为 `low + (high - low) / 2`。

**决定走哪一边。** `cmp %edi,%ecx` 按“中点减目标”设置标志位。`jle` 检查中点是否小于等于目标。

| 条件 | 执行路径 | 当前调用最后返回什么 |
|---|---|---|
| 中点 > 目标 | 设置 `edx = 中点 - 1`，递归查较小的一半 | 内层返回值 × 2 |
| 中点 = 目标 | `eax = 0`，直接收尾 | 0 |
| 中点 < 目标 | 设置 `esi = 中点 + 1`，递归查较大的一半 | 内层返回值 × 2 + 1 |

相等条件来自两次判断的结合：能进入 `0x400ff2`，说明中点 ≤ 目标；随后 `jge` 能跳到收尾，说明中点 ≥ 目标；两者同时成立，只能相等。

**递归返回之后还要继续执行。** `call func4` 保存返回地址，进入新的一次函数调用。内层返回后，外层从 `call` 后面的指令接着执行。最外层 `func4` 返回到 `phase_4`，并不是每次 `ret` 都直接回到 `main`。

```text
输入 3：
func4(3, 0, 14)，中点 7，走较小的一半
    func4(3, 0, 6)，中点 3，找到，返回 0
外层继续计算 0 × 2，最终返回 0

输入 11：
func4(11, 0, 14)，中点 7，走较大的一半
    func4(11, 8, 14)，中点 11，找到，返回 0
外层继续计算 0 × 2 + 1，最终返回 1
```

两者都经过两层调用，结果却不同，说明返回值不是次数。也不是 `0～14` 都会最终返回 0：某一层找到时返回 0，外层仍会对它进行加工。一直走较小的一半，直到相等时，0 才会逐层乘 2、保持为 0；仅仅走过一次较小的一半不能保证最终结果为 0。

将有效输入路径上的逻辑写成 C 风格伪代码，便于对照：

```c
int func4(int target, int low, int high) {
    int mid = low + (high - low) / 2;
    if (target < mid)
        return 2 * func4(target, low, mid - 1);
    if (target == mid)
        return 0;
    return 2 * func4(target, mid + 1, high) + 1;
}
```

这是对已分析汇编的语义整理，不是从实验包获得的原始 C 源码；这里只讨论 `phase_4` 限定的输入与区间。

### 4. 关键语法与易混点

**`lea` 计算，内存形式的 `mov` 读取内容。** 两者都能把结果放进寄存器，但结果的来源不同。假设 `rcx = 100`，地址 99 处存着一个整数 500：

| 指令 | 操作 | 结果 |
|---|---|---|
| `lea -1(%rcx),%edx` | 计算 `100 - 1` | `edx = 99` |
| `mov -1(%rcx),%edx` | 计算地址 `100 - 1`，再从那里读 4 字节 | `edx = 500` |

在本题中 `rcx = 7` 时，`lea -1(%rcx),%edx` 只得到 `edx = 6`，不会读取地址 6。`lea 1(%rax,%rax,1),%eax` 同理，只计算 `1 + rax + rax`。

**`test eax,eax` 为什么能检查零？** 它计算 `eax & eax`，只设置标志位，不保存结果。任何数与自己按位与还是自己：因此输入是 0 时结果为 0，`ZF = 1`；输入非零时 `ZF = 0`。后面的 `jne` 在 `ZF = 0` 时跳转，所以组合起来就是“返回值非零则爆炸”。

**寄存器的值会改变。** 调用前 `eax = 0` 是 `sscanf` 的调用准备；调用后 `eax` 是成功赋值的数量；调用 `func4` 后又变成它的返回值。`call` 本身不计算返回值，是被调用函数的代码将结果放进约定的寄存器。

**代码地址不能当字符串地址理解。** 本次草稿中曾记录 `x/s 0x400bf0` 和 `x/s 0x401044`，得到反斜杠转义组成的字符串。这些位置存的是指令，应使用 `x/i` 查看。`0x4025cf` 来自 `mov $0x4025cf,%esi`，这里存的才是 `"%d %d"`。查看方式详见第三题的 GDB 小节。

### 2. 整体解题思路

输入必须有 6 个字符。程序逐个取字符编码的低 4 位，作为下标到字符表中查询，再将查到的字符写入一个新的结果字符串。结果必须等于 `"flyers"`。

核心转换为：

```c
result[i] = table[(unsigned char)input[i] & 0xF];
```

程序正向执行“输入 → 低 4 位 → 查表 → 结果”；解题时反向推导“目标结果 → 表中下标 → 选择符合低 4 位要求的输入字符”。本次找到并验证的答案为：

```text
ionefg
```

不是直接输入 `flyers`，也不是输入二进制数字串。只要字符编码的低 4 位相同，就会选到同一个表项，因此答案不唯一。

### 3. 每个逻辑过程对应的汇编

**准备空间与输入地址。** `push %rbx → sub $0x20,%rsp → mov %rdi,%rbx`：先保存旧 rbx，预留 32 字节，再把原始输入地址复制到 rbx。rbx 是被调用者保存寄存器，便于在后续函数调用之间保留这个地址。字符串仍然在内存里，没有被整体装进寄存器。

接着 `mov %fs:0x28,%rax → mov %rax,0x18(%rsp)` 保存栈保护值（stack canary）。`%fs:0x28` 在这个 Linux 程序中访问线程的栈保护数据；不是输入或答案。`xor %eax,%eax` 将寄存器清零，不影响已经写在栈上的保护值。

**检查长度。** `call string_length → cmp $6,%eax → je 0x4010d2`：string_length 的第一个参数仍由 rdi 传递，指向原始输入。它返回字符数，不包括结束符。输入 ionefg 的长度是 6，因此跳转；长度不同则爆炸。

**初始化下标。** 跳到 `0x4010d2` 后执行 `mov $0,%eax`，将 eax 从长度值改为循环下标 0；再通过 `jmp 0x40108b` 返回地址较小的循环体。显示位置在后面不代表执行时间在后面，要跟随跳转目标。

**读取当前字符并掩码。** `movzbl (%rbx,%rax,1),%ecx` 从“输入起点 + i × 1”读取 1 字节，零扩展到 32 位。字符每个 1 字节，所以比例因子是 1。

接着 `mov %cl,(%rsp)` 写入 1 字节，`mov (%rsp),%rdx` 读取 8 字节。多读的其他字节可能是旧内容，但 `and $0xf,%edx` 只保留最低 4 位；写 edx 同时清零 rdx 的高 32 位，最后完整 rdx 的范围是 0～15。

```text
第一次处理 'i'：
ASCII 0x69 = 0110 1001
掩码  0x0F = 0000 1111
按位与结果 = 0000 1001 = 9
```

**查表并写入结果。** `movzbl 0x4024b0(%rdx),%edx` 从“表起点 + 下标”读出字符，覆盖 edx 中原有的下标。随后 `mov %dl,0x10(%rsp,%rax,1)` 把这个字符写入“结果起点 rsp + 16 + i”。第一次查到 table[9] 是 f，因此 result[0] = f。

**循环六次并结束字符串。** `add $1,%rax → cmp $6,%rax → jne 0x40108b`：下标加一，不等于 6 则继续。实际处理下标 0～5，处理完 5 后加到 6 就退出，不读取 input[6]。

`movb $0,0x16(%rsp)` 在 rsp + 22 写入 1 字节的 0。结果起点为 rsp + 16，故这里就是 result[6]，用于结束字符串。

| 相对于本函数预留空间后的 rsp | 用途 |
|---|---|
| `rsp + 0` | 暂存当前输入字符的 1 字节 |
| `rsp + 16～21` | 转换后的六个字符 |
| `rsp + 22` | 结束符 `\0` |
| `rsp + 24～31` | 保存的 8 字节栈保护值 |

**比较结果。** `mov $0x40245e,%esi` 设置第二个参数，为目标字符串地址；`lea 0x10(%rsp),%rdi` 设置第一个参数，为转换结果地址。`call strings_not_equal` 比较两者，相同返回 0，不同返回非零。

`test %eax,%eax` 做 eax 与自身的按位与，只设置标志位；eax 为 0 时 ZF = 1，`je 0x4010d9` 跳过爆炸调用。

**保护检查与返回。** `mov 0x18(%rsp),%rax → xor %fs:0x28,%rax` 检查保存的保护值。相同则结果为零，跳过 `__stack_chk_fail`；不同则触发栈保护失败处理。最后 `add $0x20,%rsp → pop %rbx → ret` 收回空间、恢复寄存器并返回。

将主要业务逻辑整理为 C 风格伪代码如下。这里省略编译器生成的栈保护代码，不是实验包的原始源码：

```c

for (int i = 0; i < 6; i++)
    result[i] = table[(unsigned char)input[i] & 0xF];

```

### 5. 关键语法与 GDB 观察

| 写法 | 含义 |
|---|---|
| `movzbl 内存,%ecx` | 读 1 字节，零扩展到 32 位；不是读 4 字节 |
| `%cl` / `%dl` | 分别是 rcx / rdx 的低 8 位 |
| `and $0xf,%edx` | 清除高位，只留下低 4 位 |
| `0x4024b0(%rdx)` | 字符表起点 + 下标；用于 mov 时读取对应内存 |
| `lea 0x10(%rsp),%rdi` | 计算结果数组的地址，不读取它的内容 |
| `movb $0,地址` | 向内存写 1 字节的零，用作字符串结束符 |
| `nopl 0x0(%rax,%rax,1)` | 多字节空操作；不改变通用寄存器、内存或标志位，也不读取括号指向的内存 |

`nopl` 通常用于填充或对齐。此处正常通过路径由前面的 je 直接跳到 0x4010d9，不经过 nopl；分析主要逻辑时不需要给它编造数据处理作用。

两次调用的第一个参数都放在 rdi，但指向的对象不同：

### 2. 整体解题思路

输入六个整数，必须都是 1～6，并且不能重复。程序把每个整数改成 `7 - 输入值`，把转换结果当作原链表中的位置编号，依次选出六个节点，再按照选出的顺序重新连接。

最后要求新链表中每个节点的数值都大于或等于下一个节点的数值，即按数值从大到小排列。

```text
六个输入整数
    ↓ 检查范围与互不重复
每个整数改为 7 - 输入值
    ↓ 按原链表的位置选择节点
保存六个节点地址
    ↓ 修改各节点的 next
组成新链表
    ↓ 检查相邻节点数值
当前值 >= 下一个值，全部满足才通过
```

解题时反过来：先读取节点数值，再按数值从大到小写出原位置，最后对每个位置计算 `7 - 位置`，得到输入。

### 3. 每个逻辑过程对应的汇编

**读取输入与保存空间。** `0x4010f4～0x40110e` 保存五个寄存器，预留 80 字节。调用 read_six_numbers 时，rdi 指向输入字符串，rsi 指向存放六个整数的内存。这个辅助函数解析六个整数；读不到六个会触发爆炸。当前 phase_6 后续直接检查内存中的整数，没有使用 eax 作为返回结果。

以下偏移均以 `sub $0x50,%rsp` 执行后的 rsp 为基准：

| 栈中位置 | 用途 |
|---|---|
| `rsp + 0、4、8、12、16、20` | 六个输入整数，每个 4 字节 |
| `rsp + 24～31` | 两个数组之间的间隔，本题逻辑未用到 |
| `rsp + 32、40、48、56、64、72` | 六个选定节点地址，每个 8 字节 |
| `rsp + 80` | 指针数组末尾后一位置，不是第七个有效槽位 |

**检查范围和重复。** `0x401114～0x401151` 是两层检查。外层令 rbp 指向当前整数，eax 临时保存这个整数减一的结果。`cmp $5,%eax → jbe` 按无符号数比较，要求结果在 0～5，所以原整数只能是 1～6。输入 0 时，减一得到 `0xffffffff`，按无符号解释很大，无法通过。这里减一只改 eax，还没有改栈中的整数。

r12d 加一后，如果已到 6 就结束检查；否则 ebx 从当前元素的后一个下标开始。`movslq %ebx,%rax` 将下标扩展到 64 位，`mov (%rsp,%rax,4),%eax` 读取对应整数。随后把它与 rbp 指向的当前整数比较，相等就爆炸。ebx 逐个加一到 5；本轮结束后 r13 加 4，开始下一轮。最终要求六个整数恰好是 1～6 的某个排列。

**逐项转换。** `0x401153～0x40116d` 中，rsi 指向整数数组末尾后一位置，rax 从起点开始。每轮先令 edx = 7，再减去 rax 指向的整数并写回，最后 rax 加 4。这里是逐项计算 `a[i] = 7 - a[i]`，不是把数组前后倒过来。

**按位置选择节点。** `0x40116f` 将 rsi 清零，接着跳到 `0x401197` 读取转换后的整数到 ecx。此时 ecx 是想选的节点位置，从 1 开始计数。如果是 1，跳到 `0x401183` 直接取头节点地址 `0x6032d0`。

如果位置大于 1，则先令 eax = 1、rdx = 头节点地址，再跳到 `0x401176`。循环中执行 `mov 8(%rdx),%rdx`，读取当前节点中的 next 地址，前进到下一个节点；eax 加一。直到 eax 等于 ecx，才结束查找。例：目标位置为 3，就从第 1 个走到第 2 个，再走到第 3 个。

`mov 8(%rdx),%rdx` 相当于 `p = p->next`。它不是把 rdx 自身加 8；加 8 是为了找到 next 字段，然后读出该字段保存的地址。

找到后，`0x401188` 把节点地址保存到 `rsp + 32 + rsi × 2`。rsi 是整数数组中的字节偏移，依次为 0、4、8、12、16、20，因此乘 2 后变成 0、8、16、24、32、40，刚好对应六个 8 字节的地址槽位。保存后 rsi 加 4；加到 24 表示六个节点都选完，跳到 `0x4011ab`。

**重新连接节点。** `0x4011ab～0x4011d2` 中，rbx 保存第一个选定节点的地址，rcx 最初也指向它。rax 指向指针数组第二个槽位，rsi 指向数组末尾后一位置。

每轮 `mov (%rax),%rdx` 取出下一个节点的地址，随后 `mov %rdx,8(%rcx)` 把它写入当前节点的 next。rax 加 8，移到下一个地址槽位；未到末尾则令 rcx = rdx，继续连接。最后 `movq $0,8(%rdx)` 把末节点的 next 清零。这里只改变连接关系，没有改变节点数值。

**检查顺序。** `0x4011da～0x4011f5` 用 ebp 记录剩余检查次数，初始为 5。先通过 `mov 8(%rbx),%rax` 取得下一个节点地址，再通过 `mov (%rax),%eax` 取得下一个节点的数值。第二条执行后，eax 已经是 int 数值，不再是地址。

`cmp %eax,(%rbx)` 按“当前节点数值减去下一个节点数值”设置标志；`jge` 是有符号大于或等于时跳转，因此要求当前值 >= 下一个值。通过后 rbx 沿 next 前进，ebp 减一，直到五对关系全部检查完毕。

下面是便于理解的 C 风格伪代码，不是原始源码：

```c
struct Node {
    int value;
    int number;
    struct Node *next;
};

int a[6];
struct Node *selected[6];
read_six_numbers(input, a);

for (int i = 0; i < 6; i++) {
    if (a[i] < 1 || a[i] > 6)
        explode_bomb();
    for (int j = i + 1; j < 6; j++)
        if (a[i] == a[j])
            explode_bomb();
}

for (int i = 0; i < 6; i++)
    a[i] = 7 - a[i];

for (int i = 0; i < 6; i++) {
    struct Node *p = head;
    for (int position = 1; position < a[i]; position++)
        p = p->next;
    selected[i] = p;
}

for (int i = 0; i < 5; i++)
    selected[i]->next = selected[i + 1];
selected[5]->next = NULL;

struct Node *p = selected[0];
for (int i = 0; i < 5; i++) {
    if (p->value < p->next->value)
        explode_bomb();
    p = p->next;
}
```

预期为 `4 3 2 1 6 5`。在转换完成、还没选择节点时停下：

```gdb
break *0x40116f
continue
x/6dw $rsp
```

预期为 `3 4 5 6 1 2`。在六个节点已经选好、还没重新连接时停下：

```gdb
break *0x4011ab
continue
x/6gx $rsp+0x20
```

预期六个地址依次为 `0x6032f0、0x603300、0x603310、0x603320、0x6032d0、0x6032e0`。若还设有其他断点，continue 可能先停在那里，先核对当前位置再观察对应数据。

重新连接后，next 已经改变；要观察原链表，应重新运行并停在重连之前。节点本身的数值在这个过程中不变。
